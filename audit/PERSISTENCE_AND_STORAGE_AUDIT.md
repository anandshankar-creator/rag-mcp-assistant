# Persistence and Storage Architecture Audit

**Project**: RAG-Based Multi-Agent Personal Assistant Using MCP  
**Environment**: Streamlit Community Cloud (Stateless Ephemeral Linux Containers)  
**Audit Scope**: SQLite, ChromaDB Vector Store, PDF File Output, OAuth State, Session Tokens  
**Audit Date**: October 2026  

---

## 1. Streamlit Community Cloud Storage Characteristics

Streamlit Community Cloud executes applications within lightweight, stateless Docker containers:
1. **Stateless Ephemeral Disks**: Changes written to the local disk during runtime (e.g., files in `db/`, `outputs/`, or `data/`) persist while the container remains active, but are wiped whenever the container restarts, sleeps after inactivity, or re-deploys from GitHub.
2. **Immutable Git Baseline**: Any files tracked and committed in Git (e.g., sample documents in `data/documents/`) are restored to their committed state on every fresh container boot.
3. **In-Memory Volatility**: Python global variables and session state persist across interactions within an active browser session, but reset on page reloads unless statefully re-hydrated.

## 2. Storage Subsystem Audit & Mitigations

### 2.1 SQLite Relational Database (`db/assistant.db`)

#### Tables Managed:
- `admin_credentials`: Stores the single administrator account (`email`, bcrypt `password_hash`, `auth_version`).
- `login_attempts`: Tracks failed authentication counts and lockout timestamps for brute-force protection.
- `password_reset_tokens`: Stores single-use SHA-256 token hashes and expiration timestamps.
- `revoked_tokens`: Blacklists JWT session IDs (`jti`) upon explicit logout.
- `reset_request_attempts`: Rate limits password reset requests (maximum 3 per 15-minute window).
- `user_preferences`: Stores user and administrator profile settings (`admin_name`, `name`, `timezone`).
- `reminders`: Stores task reminders and deadlines.
- `calendar_events`: Stores academic schedule events.
- `notes`: Stores local notes.
- `action_audit_log`: Stores execution receipts and parameter audit logs for conversation context awareness.

#### Cloud Ephemeral Risk:
On container rebuilds, an un-backed SQLite database reverts to the initial state.

#### Implemented Mitigations:
1. **Idempotent Seeding & Migration**: On every application startup, `app/auth.py` executes `init_auth_tables()` and `_seed_admin_account_if_needed()`. If the database is freshly created or missing, it automatically seeds canonical administrator `sergio759516@gmail.com` with secure password hashing.
2. **Stale Lockout Eviction**: When the canonical administrator email is synchronized, stale lockout records are purged automatically, preventing accidental lockouts on container cold boots.
3. **Production Path Forward**: For multi-instance horizontal scaling, the SQLite abstraction in `app/auth.py` and `mcp_servers/db.py` can be swapped with PostgreSQL (e.g., Supabase / Neon) via SQLAlchemy without changing tool schemas.

### 2.2 ChromaDB Vector Store (`db/chroma/`)

#### Data Stored:
- 384-dimensional dense vector embeddings generated by `sentence-transformers/all-MiniLM-L6-v2`.
- Text chunks extracted from university syllabi, academic regulations, and study guides.
- Metadata dictionaries containing `source_file`, `page_number`, `chunk_id`, and `character_span`.

#### Cloud Ephemeral Risk:
If ChromaDB files are modified at runtime on Streamlit Cloud, newly uploaded documents could be lost if the container reboots.

#### Implemented Mitigations:
1. **Pre-Indexed Baseline Syllabi**: Core KTU syllabi and study guides are kept in `data/documents/` and pre-indexed in the repository baseline.
2. **Fast On-Demand Ingestion**: The Knowledge Base Manager in `ui/streamlit_app.py` allows administrators to re-index any document (`.pdf`, `.docx`, `.txt`, `.md`) in under 3 seconds using the local CPU embedding model.
3. **Fail-Soft Web Fallback**: If a query targets topics not indexed in the local vector store, the agent triggers trusted web search fallback (prioritizing `.edu`, `.ac.in`, and official university portals), ensuring continuous availability.

### 2.3 PDF Output Generation (`outputs/`)

#### Data Managed:
- Compiled PDF documents generated by ReportLab (`outputs/<filename>.pdf`).

#### Cloud Ephemeral Risk:
Generated PDF files written to disk are inaccessible to external web browsers unless served through Streamlit. Furthermore, Streamlit re-runs script execution on every user interaction, which could wipe temporary local download references.

#### Implemented Mitigations:
1. **In-Memory PDF Cache Registry**: When `pdf_server.generate_pdf()` compiles a document, `ui/streamlit_app.py` caches the binary PDF bytes in `st.session_state.pdf_registry[filename]`.
2. **Native Streamlit Download Button**: A persistent `st.download_button()` is rendered directly in the chat interface and sidebar. This serves the PDF directly from memory as an `application/pdf` stream, completely immune to container disk resets.

---

### 2.4 Google OAuth Tokens & API Secrets

#### Data Managed:
- Desktop OAuth 2.0 client secrets (`client_id`, `client_secret`).
- Authorized user tokens (`access_token`, `refresh_token`, `token_uri`, `scopes`).

#### Cloud Ephemeral Risk:
Writing `google_token.json` to the container filesystem is lost on restart, and interactive browser login cannot run in headless cloud containers.

#### Implemented Mitigations:
1. **Zero-Disk Secret Loading**: `GoogleAuthManager` reads `GOOGLE_TOKEN_JSON` or `[google_oauth]` directly from `st.secrets`.
2. **In-Memory Token Refresh**: Access tokens are refreshed in-memory using Google Auth requests without requiring container disk writes.
3. **Direct SMTP Alternative**: `email_server.py` supports standard Gmail SMTP via `GMAIL_USER` and `GMAIL_APP_PASSWORD` in `st.secrets`, requiring zero OAuth token caching.

## 3. Summary of Storage Durability

| Subsystem | Storage Mechanism | Localhost Durability | Streamlit Cloud Durability | Mitigation / Strategy |
|-----------|-------------------|----------------------|----------------------------|------------------------|
| **Admin Auth & Lockout** | SQLite (`assistant.db`) | Permanent | Ephemeral per container | Automated bootstrap migration on boot |
| **Vector Index** | ChromaDB (`db/chroma`) | Permanent | Ephemeral per container | Pre-indexed Git baseline + fast re-indexing |
| **PDF Downloads** | ReportLab + `outputs/` | Permanent | Ephemeral per container | Memory byte caching + native Streamlit button |
| **User Preferences** | SQLite (`user_preferences`) | Permanent | Ephemeral per container | Dual key persistence (`admin_name`, `name`) |
| **Google OAuth** | `st.secrets` / JSON | File cached | In-memory from secrets | Direct secret loading via `Credentials.from_authorized_user_info()` |
